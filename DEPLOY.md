# Деплой на Fly.io

Бот работает на long polling: входящий трафик, домен и HTTPS ему не нужны. На Fly это одна
машина без веб-сервиса, с постоянным диском под базу.

## Что важно понять до начала

**База остаётся SQLite, файл лежит на постоянном диске Fly.** Это осознанный выбор: боту
всё равно нельзя запускать больше одного экземпляра (Telegram отдаёт `getUpdates` только
одному потребителю на токен), поэтому распределённая база не нужна. Диск Fly переживает
редеплои и перезапуски, а Fly раз в сутки делает снапшоты. Postgres добавил бы второй
сервис, деньги и пересоздание всех миграций — без выигрыша для одного инстанса.

**Локальная база не переедет.** На Fly создаётся пустой диск, так что после деплоя надо
заново нажать `/start` в боте. Если хочется перенести — см. «Перенос локальной базы» ниже.

**Перед деплоем остановите локального бота** (`Ctrl+C` в терминале, где запущен `npm run dev`).
Два процесса на одном токене дают `409 Conflict`, и они начнут выбивать друг друга.

**Стоимость.** Машина `shared-cpu-1x` с 512 МБ — примерно $3–4 в месяц, диск 1 ГБ — ещё
$0.15. Бесплатного тарифа у Fly для новых аккаунтов нет, карту привязать придётся.

## Первый деплой

```bash
# 1. Установить CLI и войти
#    Windows PowerShell:
iwr https://fly.io/install.ps1 -useb | iex
fly auth login

# 2. Создать приложение (имя должно быть свободным на весь Fly)
fly apps create ftp-telegram-bot

# 3. Создать диск под базу в том же регионе, что в fly.toml
fly volumes create data --region fra --size 1

# 4. Положить секреты (в fly.toml их держать нельзя)
fly secrets set BOT_TOKEN=8848474402:ВАШ_ТОКЕН ADMIN_IDS=353592796

# 5. Деплой — Fly собирает образ у себя, локальный Docker не нужен
fly deploy
```

Регион `fra` — Франкфурт. Бухарест (`otp`) и Варшава (`waw`) закрыты Fly для новых
ресурсов, поэтому ближайший доступный — Франкфурт. Для бота задержка почти не важна, он сам ходит к серверам Telegram.

## Проверка после деплоя

```bash
fly logs           # должно быть: applying migrations → seeding → Bot is running
fly status         # одна машина в состоянии started
```

В логе при старте вы увидите:

```
→ applying migrations
→ seeding sports and quiz questions
INFO: Database connected
INFO: Digest scheduler started {"times":["10:00","19:00"],"timezone":"Europe/Chisinau"}
INFO: Bot is running
```

После этого напишите боту `/start` в Telegram и `/admin` — если статистика открылась,
`ADMIN_IDS` доехал.

## Обновление кода

```bash
git push            # если деплоите из репозитория
fly deploy
```

Стратегия деплоя в `fly.toml` — `immediate`: старая машина останавливается раньше, чем
поднимается новая. Так и должно быть, иначе два экземпляра поспорят за токен. Бот будет
недоступен секунд 20–30, апдейты за это время Telegram сохранит и отдаст после старта.

## Бэкапы

Fly сам делает снапшоты диска раз в сутки (хранит 5 дней):

```bash
fly volumes list                        # узнать id диска
fly volumes snapshots list <volume-id>
```

Скачать базу себе:

```bash
fly ssh sftp get /data/dev.db ./backup-$(date +%F).db
```

Восстановить из своего файла:

```bash
fly ssh sftp shell
put ./backup-2026-09-10.db /data/dev.db
exit
fly apps restart ftp-telegram-bot
```

## Перенос локальной базы

Если хочется сохранить профили, которые вы создали локально:

```bash
# на первом деплое база уже создана миграциями, её можно перезаписать
fly ssh sftp shell
put ./prisma/dev.db /data/dev.db
exit
fly apps restart ftp-telegram-bot
```

Перед этим уберите тестовые профили: `npm run test-players clear`.

## Полезные команды

| Команда | Что делает |
| --- | --- |
| `fly logs` | Живой лог |
| `fly logs --no-tail` | Последние строки и выход |
| `fly status` | Состояние машины |
| `fly apps restart ftp-telegram-bot` | Перезапуск |
| `fly ssh console` | Shell внутри контейнера |
| `fly secrets list` | Какие секреты заданы (значения не показываются) |
| `fly scale count 1` | Убедиться, что машина одна |
| `fly machine stop <id>` | Остановить бота, не удаляя приложение |

## Три грабли, на которые уже наступили

Всё это уже исправлено в `fly.toml` и в workflow, но знать полезно.

**Секреты в статусе `Staged`.** Если положить секрет через API или с флагом `--stage`, он
попадёт в хранилище, но ни в один релиз — машина стартует без него. `flyctl secrets set`
с тем же значением релиз не создаёт, потому что менять нечего. Лечится `fly secrets deploy`.
Проверить: `fly secrets list` — в колонке STATUS не должно быть `Staged`.

**Fly Launch перезаписывает `fly.toml`.** Он создаёт в репозитории PR «New files from Fly.io
Launch» с конфигом веб-приложения: `internal_port = 3000`, `auto_stop_machines = 'stop'`,
`min_machines_running = 0`. Для бота на long polling это смертельно — HTTP-трафика нет,
и Fly останавливает машину через пару секунд. Такой PR мёрджить нельзя.

**Остановленная машина остаётся остановленной.** Деплой обновляет конфиг машины, но не
запускает её: Fly ждёт, что её разбудит HTTP-запрос. Бот такого запроса не получает никогда.
Поэтому в workflow есть шаг, который поднимает все не-`started` машины.

## Чего делать нельзя

- **Не масштабировать выше одной машины.** `fly scale count 2` сломает бота: два процесса
  начнут забирать одни и те же апдейты и получать `409 Conflict`.
- **Не запускать локальный `npm run dev` при работающем деплое** — та же причина.
- **Не хранить токен в `fly.toml`.** Файл лежит в репозитории, секреты — только через
  `fly secrets set`.
- **Не добавлять `[http_service]`** в `fly.toml`. Появится веб-сервис, а вместе с ним и
  автостоп машины при отсутствии запросов — бот будет засыпать.

## Переход на PostgreSQL, если понадобится

Понадобится, когда захочется несколько инстансов, аналитика по базе или Prisma Studio
из другого места. Тогда:

1. В `prisma/schema.prisma` заменить `provider = "sqlite"` на `"postgresql"`.
2. Удалить `prisma/migrations` и создать заново: `npx prisma migrate dev --name init`.
3. `fly postgres create`, затем `fly postgres attach <имя>` — он положит `DATABASE_URL`
   в секреты приложения.
4. Убрать `DATABASE_URL` из `[env]` в `fly.toml`, чтобы он не перекрывал секрет,
   и убрать блок `[mounts]`.
5. `fly deploy`.

Схема специально написана переносимо: без нативных enum, массивов и JSON-колонок.
