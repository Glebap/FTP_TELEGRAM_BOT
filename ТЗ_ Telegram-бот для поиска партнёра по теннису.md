# Telegram Bot — поиск партнёра для тенниса

## 1. Цель проекта

Создать Telegram-бота для поиска партнёров для игры в теннис.

Основной пользовательский сценарий:

1. Пользователь регистрируется.
2. Указывает основные параметры:
   - страна;
   - возраст;
   - уровень игры;
   - дополнительные предпочтения;
   - фотографию;
   - короткий текст о себе.
3. Если пользователь не знает свой уровень, бот предлагает короткий тест примерно из 10 вопросов и автоматически определяет приблизительный уровень.
4. После регистрации пользователь нажимает **«Найти партнёра»**.
5. Бот показывает подходящих игроков по одному.
6. Пользователь может:
   - перейти к следующему игроку;
   - открыть профиль;
   - написать игроку.
7. В дальнейшем систему необходимо расширить на другие виды спорта.

---

# 2. Основной принцип

По UX бот должен быть похож на сервисы знакомств типа «Дайвинчик»:

**Найти партнёра → показать профиль → Следующий / Написать**

При этом это не dating-приложение. Цель системы — найти человека для совместной спортивной активности.

Основной объект поиска:

> Игрок → подходящий спортивный партнёр → контакт

---

# 3. Поддерживаемые виды спорта

На первом этапе:

- Tennis

Архитектура должна изначально поддерживать несколько видов спорта.

Например:

```text
Sport
 ├── Tennis
 ├── Padel
 ├── Badminton
 ├── Table Tennis
 └── Basketball
```

Нельзя делать теннисную логику полностью захардкоженной.

Каждый пользователь должен иметь:

```text
sport
```

или несколько спортивных профилей в будущем.

Например:

```text
User
 ├── basic information
 ├── tennis profile
 └── future sport profiles
```

Пользователь указывает возраст.

В интерфейсе лучше использовать кнопки или пошаговый выбор, а не заставлять вводить произвольный текст.

Например:

```text

20
21
22
...
```

Минимальный возраст для MVP:

**18 лет**

Возраст хранится числом:

```text

```

Дата рождения для MVP не требуется.

Пример:


Основной принцип matching:

```text

```

# 10. Если пользователь не знает уровень

При выборе:

**«Не знаю свой уровень»**

бот запускает короткий тест.

Тест должен состоять примерно из **10 вопросов**.

Цель теста — получить приблизительную оценку уровня игрока.

Важно:

> Результат теста является приблизительной оценкой, а не официальной классификацией NTRP.

# 12. Алгоритм определения уровня

Каждый ответ имеет score.

Например:

```text
answer score:
1 = beginner
2 = low beginner
3 = intermediate
4 = upper intermediate
5 = advanced
```

После завершения теста рассчитывается итоговый score.

Пример:

```text
average_score = 3.4
```

После этого применяется mapping:

```text
1.0–1.7 → 2.5
1.8–2.5 → 3.0
2.6–3.5 → 3.5
3.6–4.3 → 4.0
4.4–5.0 → 4.5+
```

Точная формула должна находиться в отдельном конфигурационном модуле, чтобы её можно было менять без изменения основной логики приложения.

# 18. Принцип поиска

Для MVP использовать простую scoring-систему.

Каждый потенциальный партнёр получает score.

Например:

```text
same city          +40
same country       +20
similar level      +25
similar age        +10
has photo          +5
```

Пример:

```text
Player A = 95
Player B = 70
Player C = 52
```

Сначала показывать игроков с большим score.

Уровень должен иметь определённый диапазон совместимости.

Например:

```text
3.5 → 3.0 / 3.5 / 4.0
```

То есть не обязательно искать только людей с идентичным уровнем.

# 20. Кнопка «Следующий»

При нажатии:

**Следующий**

текущего пользователя не нужно показывать повторно.

Система должна запоминать, кого текущий пользователь уже просмотрел.

Создать сущность:

```text
ProfileView
```

или:

```text
Swipe
```

Например:

```text
viewer_id
viewed_user_id
action
created_at
```

Где action:

```text
next
like
message
```

Для MVP можно хранить только факт просмотра.

# 21. Кнопка «Написать сообщение»

При нажатии:

**💬 Написать**

есть два возможных сценария.

### Вариант MVP

Бот показывает:

> Вы можете начать общение с Алексом.

И кнопку:

**💬 Открыть Telegram**

Если у пользователя есть публичный username:

```text
https://t.me/username
```

---

### Более правильный вариант

Сделать внутренний relay через бота.

Пользователь A пишет сообщение боту:

> Привет! Давай сыграем на выходных.

Бот отправляет его пользователю B:

> 💬 Новое сообщение от игрока Алекс, NTRP 3.5

При этом Telegram username можно не раскрывать.

В ответ:

```text
↩️ Ответить
```

Для MVP рекомендуется реализовать именно relay-механику, потому что она позволяет сохранить пользователей внутри системы.

# 30. Обработка неправильного ввода

Бот не должен падать, если пользователь:

- отправил текст вместо числа;
- отправил фотографию там, где ожидается текст;
- написал слишком длинный текст;
- нажал старую inline-кнопку;
- начал регистрацию повторно.

Вместо этого показывать понятное сообщение:

> Пожалуйста, выберите вариант из кнопок ниже.

# 36. Matching Service

Matching должен быть отдельным сервисом:

```python
MatchingService
```

Пример:

```python
find_candidates(
    user_id,
    sport_id,
    limit=20
)
```

Он должен:

1. Получить профиль текущего пользователя.
2. Найти активных пользователей того же спорта.
3. Исключить самого пользователя.
4. Исключить уже просмотренных пользователей.
5. Применить фильтры.
6. Рассчитать compatibility score.
7. Отсортировать пользователей.
8. Вернуть следующие профили.

# 37. Compatibility Score

Пример:

```python
score = 0

if same_city:
    score += 40

if same_country:
    score += 20

if level_difference == 0:
    score += 25
elif level_difference == 0.5:
    score += 20
elif level_difference == 1.0:
    score += 10

if age_difference <= 3:
    score += 10
elif age_difference <= 7:
    score += 5

if has_photo:
    score += 5
```

Все коэффициенты должны быть вынесены в настройки.

# 39. Поддержка нескольких видов спорта

Хотя MVP создаётся для тенниса, код должен быть примерно такого типа:

```python
sport = Sport(
    name="Tennis",
    slug="tennis"
```

Вместо:

```python
if sport == "tennis":
    ...
```

в многочисленных местах кода.

Логика должна быть максимально общей.

Специфичные для спорта параметры должны быть конфигурируемыми.

Например:

# 48. Главная продуктовая идея

Продукт должен ощущаться не как обычный Telegram-бот, а как:

> **«Дайвинчик для поиска спортивного партнёра».**

Основной цикл продукта:

```text
Профиль
   ↓
Поиск
   ↓
Карточка игрока
   ↓
Следующий
   ↓
Интерес
   ↓
Сообщение
   ↓
Совместная игра
```

Главная ценность:

**быстро найти человека примерно своего уровня рядом с собой и начать общение.**
